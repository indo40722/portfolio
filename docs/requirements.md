# ポートフォリオサイト 要件定義書

## 目的

公開名 `Akihiro` のポートフォリオとして、制作経験、担当範囲、成果、学習中の技術を短時間で確認できるWebサイトを作成する。

## 対象利用者

- 新卒採用の面接官、現場エンジニア、インターン選考担当者
- 本人が面接前に実績を整理するための確認者

## 技術構成

- React
- TypeScript
- Vite
- GitHub Pages
- GitHub Actions

## 公開要件

- GitHub Pagesで静的サイトとして公開できること。
- `main` または `master` へのpushで自動ビルド・自動デプロイできること。
- `username.github.io` リポジトリと通常リポジトリの両方に対応できるよう、workflow内でViteのbase pathを切り替えること。

## 表示要件

- ファーストビューで氏名、学校、志望軸、代表的な成果が分かること。
- 代表実績として、VCL、Hoppy、学生データ分析AWARD 2025、コールセンターでの成果を扱うこと。
- 作品一覧はカテゴリフィルターを置かず、代表作品を一覧で確認できること。
- VCL、Hoppyなど制作画面が残っている作品は、実際の画面・資料画像を作品カードに表示すること。
- Hoppyの開発時間は、個人の作業時間ではなく「チーム合計開発時間」として伝えること。
- 学生データ分析AWARD 2025は、公開されているインタビュー記事への外部リンクを掲載できること。
- 学生データ分析AWARD 2025は代表作品として内容を見せつつ、Awards一覧にも受賞履歴として掲載すること。
- 代表作品とは別に、学内コンペやHAL EVENT WEEKなどの受賞歴を一覧で確認できること。
- プロトタイプ開発の銅賞は、別作品ではなくVCLの初期プロトタイプとして記載すること。
- テラッカソン10thのkakeruXテーマで得た個人賞とチーム賞を、受賞歴として確認できること。
- 強み、技術、連絡先の各セクションを持つこと。
- 右下に常駐する相談ボタンから、ChatGPT、Claude、Gemini、Perplexityにポートフォリオ相談用プロンプトを渡せること。
- AIが読み取りやすい公開Markdownとして `profile.md` を提供し、サイト構造の案内として `llms.txt` を提供すること。
- Awardsが制作・受賞の時系列を兼ねるため、Timelineセクションは設けないこと。
- モバイル幅でも文字やボタンがはみ出さないこと。
- ヒーロー内のCTAボタンと実績サマリーは、画面幅や高さが変わっても重ならないこと。
- 視覚素材を用い、制作経験の雰囲気が伝わること。
- ブラウザタブで識別できるfaviconを持つこと。

## 内容方針

- 軸は「ユーザーの困りごとを見つけ、技術で使いやすい形にする」に置く。
- 技術名だけでなく、担当範囲、判断、成果、再現性が伝わる文章にする。
- チームで考えた企画と本人が担当した制作範囲を混同せず、本人の担当はWebサイト制作、画面構成、画面実装など具体的な作業で書く。
- セクション見出しは特定技術の学習アピールに寄せすぎず、制作内容、役割、成果が先に伝わる表現にする。
- Works、Awards、Skillsの見出し横には説明文を置かず、必要な情報は作品カード、受賞行、技術カードに集約する。
- 強みセクションでは抽象的な説明文を増やしすぎず、各カードの具体例で伝える。
- サイト本文、メタ情報、READMEではフルネームを出さず、公開名 `Akihiro` を使う。
- 技術セクションは学習予定だけの見せ方を避け、説明文を増やしすぎず、制作経験に紐づく技術をカードとタグで整理する。
- 具体性の薄い技術タグは置かず、面接時に担当内容と結びつけて説明できるものだけを表示する。
- アーティストサイト制作など第三者の肖像・公式素材が関わる経験は、公開版では本人写真や公式素材を使わず、制作意図と受賞結果を中心に記載する。
- 個人情報が強い応募フォーム用データは読み込まず、公開して問題ない内容だけを掲載する。

## 実装方針

- Reactコンポーネント名は大文字始まりにする。
- Hooksはコンポーネントのトップレベルで呼び出す。
- 表示データは `src/content/portfolio.ts` に集約し、画面実装と内容を分離する。
- 作品一覧は表示用stateを持たず、`featuredProjects` をそのまま描画する。
- TypeScriptの型で作品、スキル、受賞歴の構造を明示する。
- 作品画像や外部リンクは任意項目として型定義し、データがある場合だけReact側で表示する。
- 受賞歴は表示データとして `src/content/portfolio.ts` に集約し、コンポーネント側は一覧表示に専念する。
- AI相談ボタンは表示状態だけをReact stateで持ち、プロンプト本文はページURL、Markdown URL、llms.txt URLから生成する。
- `id` はページ内アンカー、ARIA参照、固有ランドマークに使い、再利用する見た目や状態表現には `className` を使う。
- 1回しか使わない装飾用classは、既存の意味ある `id` や共有classで表現できないか確認してから追加する。
- GitHub上の差分が読みやすいよう、リポジトリのテキストファイルはLF改行で扱う。

## デザイン方針

- 汎用的な白背景と紫グラデーションのテンプレート感を避ける。
- 実験室的な開発ボードをモチーフに、VCL、Hoppy、データ分析の経験がつながって見える画面にする。
- 色はオフホワイト、インクブラック、ティール、アンバー、赤を役割ごとに使い分ける。
- セクションは全幅の帯と制約幅レイアウトで構成し、カードの入れ子は避ける。
- ヒーローの文字サイズは、強い第一印象を残しながら作品一覧へ視線が流れる大きさに抑える。
- セクション見出しは不自然な折り返しにならない長さに抑え、WorksとStrengths見出しは短い断定文にする。
- ヘッダーはロゴ風の頭文字シンボルを置かず、公開名 `Akihiro` と補足テキストだけで構成する。
- 右下の相談ボタンはクエスチョンマークのアイコンのみで表示し、本文や主要CTAより目立ちすぎないサイズにする。
